# Таблица ролей RBAC для Kubernetes кластера PropDevelopment

## Обоснование ролевой модели

На основе анализа организационной структуры PropDevelopment выделены следующие группы пользователей:

1. **Администраторы инфраструктуры** - требуют полного доступа к кластеру
2. **Специалист по ИБ** - требует привилегированного доступа для аудита безопасности
3. **Команды разработки** - требуют доступа для деплоя и управления приложениями
4. **Команды мониторинга** - требуют read-only доступа для наблюдения за системами

## Таблица ролей

| Роль | Права роли | Группы пользователей |
| --- | --- | --- |
| **cluster-admin** | **Полный доступ ко всем ресурсам кластера:**<br>- Создание, изменение, удаление всех ресурсов<br>- Управление RBAC (роли, привязки)<br>- Доступ к секретам всех namespace<br>- Управление узлами кластера<br>- Управление PersistentVolumes<br>- Управление CustomResourceDefinitions | **Администраторы инфраструктуры:**<br>- Руководитель IT-отдела<br>- Старший DevOps-инженер<br>- Системные администраторы |
| **security-auditor** | **Привилегированный доступ для аудита безопасности:**<br>- Просмотр всех ресурсов во всех namespace (get, list, watch)<br>- Просмотр секретов (только чтение)<br>- Просмотр RBAC конфигураций<br>- Просмотр логов всех подов<br>- Просмотр событий (events)<br>- Просмотр NetworkPolicies<br>**Запрещено:** создание, изменение, удаление ресурсов | **Специалисты по информационной безопасности:**<br>- Специалист по ИБ<br>- Аудиторы безопасности<br>- Compliance-менеджеры |
| **namespace-editor** | **Полный доступ для работы с приложениями в namespace:**<br>- Создание, изменение, удаление: Deployments, Services, ConfigMaps, Secrets<br>- Управление RBAC внутри namespace<br>- Просмотр и управление логами<br>- Exec в поды для отладки<br>- Port-forward для разработки<br>- Управление ResourceQuotas и LimitRanges<br>**Запрещено:** изменение самого namespace, управление узлами | **Команды разработки и эксплуатации:**<br>- Владельцы продуктов<br>- DevOps-инженеры<br>- Backend-разработчики<br>- Frontend-разработчики<br>- Технические лиды |
| **namespace-viewer** | **Только чтение в namespace:**<br>- Просмотр всех ресурсов (get, list, watch)<br>- Просмотр логов (без exec)<br>- Просмотр событий и метрик<br>- Просмотр статуса подов и сервисов<br>**Запрещено:** любые изменения, просмотр секретов, exec в поды | **Мониторинг и бизнес:**<br>- Инженеры по эксплуатации<br>- SRE-инженеры<br>- Бизнес-аналитики<br>- Менеджеры продуктов<br>- Аналитики BI<br>- Бухгалтеры |

## Распределение ролей по доменам (namespace)

### Namespace: `sales` (Группа сервисов для продаж)
- **namespace-editor**: owner-sales, devops-sales, dev-backend-sales, dev-frontend-sales
- **namespace-viewer**: ops-sales, analyst-clients

### Namespace: `tenant-services` (Группа сервисов ЖКУ)
- **namespace-editor**: owner-tenant, devops-tenant, dev-backend-tenant, dev-smarthome
- **namespace-viewer**: ops-tenant, analyst-zku

### Namespace: `finance` (Финансы)
- **namespace-editor**: owner-finance, dev-finance
- **namespace-viewer**: ops-finance, accountant

### Namespace: `data` (Дата - обработка данных)
- **namespace-editor**: owner-data, dev-data
- **namespace-viewer**: ops-monitoring, analyst-bi

## Принципы безопасности

1. **Принцип минимальных привилегий**: Каждая роль имеет только необходимые права для выполнения своих задач
2. **Разделение обязанностей**: Разработчики (editor) отделены от наблюдателей (viewer)
3. **Изоляция доменов**: Каждый домен работает в своем namespace с собственными правами
4. **Аудит**: Роль security-auditor позволяет специалисту по ИБ контролировать безопасность без возможности внесения изменений
5. **Ограничение привилегированного доступа**: Только 2-3 администратора имеют cluster-admin права

## Дополнительные меры безопасности

1. **NetworkPolicies**: Ограничение сетевого взаимодействия между namespace
2. **ResourceQuotas**: Ограничение ресурсов для каждого namespace
3. **Audit Logging**: Логирование всех действий пользователей с ролями namespace-editor и выше
4. **Регулярный пересмотр прав**: Ежеквартальный аудит назначенных ролей
